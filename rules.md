
### 1. Prerequisites (Before You Begin)
*   [ ] The AI platform you are going to use is downloaded and set up on your system.
*   [ ] Git is installed and configured.
*   [ ] You have an active GitHub account.
*   [ ] You are able to create and manage public repositories.

### 2. Important Rules (Strict Compliance)
*   [ ] **Maximum 3 attempts allowed.**
*   [ ] **The repository size must be less than 10 MB.**
*   [ ] **The GitHub repository must be public.**
*   [ ] **The repository should contain only one branch.**
*   *Warning:* Failure to follow these rules may result in your submission not being evaluated.

### 3. Challenge Expectations
Your solution should demonstrate:
*   [ ] Ability to build a smart, dynamic assistant.
*   [ ] Logical decision making based on user context.
*   [ ] Practical and real-world usability.
*   [ ] Clean and maintainable code.
*   *Note:* Participants must choose one of the provided challenge verticals and design their solution around that persona and logic.

### 4. How to Work on Your Project
*   [ ] Create a new repository on GitHub.
*   [ ] Ensure the repository is set to public.
*   [ ] Open your AI platform.
*   [ ] Clone your repository inside the AI platform.
*   [ ] Build your solution through prompting and coding.
*   [ ] Regularly commit and push your progress.
*   [ ] Keep all work within a single branch.

### 5. What to Submit
Your submission must include:
*   [ ] A public GitHub repository link.
*   [ ] Complete project code inside the repository.
*   [ ] A `README` explaining:
    *   [ ] Your chosen vertical.
    *   [ ] Approach and logic.
    *   [ ] How the solution works.
    *   [ ] Any assumptions made.

### 6. Evaluation Focus Areas
Submissions will be reviewed on:
*   [ ] **Code Quality** – structure, readability, maintainability.
*   [ ] **Security** – safe and responsible implementation.
*   [ ] **Efficiency** – optimal use of resources.
*   [ ] **Testing** – validation of functionality.
*   [ ] **Accessibility** – inclusive and usable design.
*   [ ] **Problem Statement Alignment** – relevance to the stated problem.

### 7. Impact Tiers (How you are scored)
Your score in each tier directly shapes your final result:
*   **High Impact:** The most important parts of your project. Doing great here will heavily drive a high overall score. (Missing these drastically lowers your standing).
*   **Medium Impact:** How well your solution works under the surface. (Doing great here steadily elevates your score).
*   **Low Impact:** Final layers of polish. (Excelling here gives a small boost, but you still need them for a perfect score).

### 🚨 CRITICAL WARNINGS FOR YOUR BUILD

Based on these rules, here are the 3 most dangerous things you could do:
1.  **Pushing `node_modules`:** If you run `git add .` without a `.gitignore` file, your repo will instantly be 200+ MB, and you will be **disqualified**.
2.  **Committing your `.env` file:** If you push your OpenAI/Gemini API key, it violates the "Security" evaluation, and bots will steal your key. Use a `.env.example` file instead.
3.  **Missing the README sections:** The rules explicitly ask for 4 specific things in the README. Copy the template I provided in the previous step to guarantee you don't lose these points.
